# 阶段 5B：Checkpoint 恢复入口

更新日期：2026-08-14

本增量补齐应用重启后的 Checkpoint 发现与显式加载入口。Rust 只向界面返回任务 ID、文件名、恢复后阶段、输出模式、分段计数和更新时间，最多 100 条；文件路径、正文、译文、模型地址、提示词、术语表和原始错误均不进入摘要。

工作台会自动检查本机可恢复任务，并允许用户显式加载完整 Checkpoint。加载只恢复本机状态，不会自动发送网络请求，也不会创建输出文件。损坏、未来版本、目录不匹配和非恢复终态不会进入列表；只读发现不会隔离或删除这些文件，既有显式加载与清理边界保持不变。

第二增量已接通恢复执行：继续前只从当前安全配置读取 API Key，并在任何新 Checkpoint 写入前逐字段校验模型、服务地址、语言、提示词和术语表。`ready` 任务复用既有队列且跳过成功段；`failed` 任务只把可重试失败段恢复为待处理，成功段和永久失败段保持不变。配置缺失或漂移只返回稳定本地化错误，不覆盖原任务，也不显示原始错误详情。

第三增量已经接通 DOCX 重建、最终导出和任务级取消。翻译队列完成后会重新检查源文件，再保存 `exporting` Checkpoint，随后在阻塞线程中重建、校验并原子发布新文件；发布成功后保存 `completed` 状态，界面只显示输出文件名，不暴露完整路径。

取消边界以原子发布为提交点：提交前可以停止并清理临时文件；发布开始后取消请求会被拒绝，实际成功结果优先，避免“文件已存在但界面显示取消”的冲突。应用重启后，已完成全部译文但中断在重建/导出的 Checkpoint 可以直接继续导出，不读取 API Key，也不重新发送翻译请求。

本增量已覆盖自动重建、提交前取消、提交后成功优先、重启恢复和稳定错误码。PDF、发布版本提升及无关优化仍不混入本阶段；真实 Word/LibreOffice 兼容性仍需在发布收口阶段使用代表性文档矩阵验证。
