1. 把 `lib.rs` 剩余诊断与更新器状态入口迁入对应领域模块，并逐步统一 Tauri 错误。
2. 三处版本提升到 `0.4.9`，创建版本化发布说明并构建候选安装包。
3. 使用候选安装包执行 `RELEASE_DESKTOP_SMOKE.md`，记录 SHA-256、操作者和结果，并验证从 `v0.4.8` 应用内升级。
4. 发布并核验 `v0.4.9` 的 EXE、MSI、Updater 签名、`latest.json` 和质量报告。
5. 从最新 `master` 开始 `v0.5.0`：先实现最小 Native Host，再实现私有 IPC、配对、Manifest V3 service worker，最后进入扩展 UI。

详细风险、证据和阶段退出门槛见 `DEVELOPMENT_STATUS_2026-07-30.md`。

## 每一步的交付要求

- 每次只做一个边界清晰的改动，并补对应测试。
- 运行 `npm test`、`npm run build`、`npm run audit:bundle`、`npm audit`、`cargo test`、`cargo clippy` 和质量报告。
- 更新本说明或开发计划，显式提交文件，推送分支并等待 GitHub CI 通过。
- 不提交 `releases/` 下的历史本地安装包，也不在代码、日志或文档中写入密钥。
