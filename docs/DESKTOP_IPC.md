# 浏览器桥接桌面私有 IPC

状态：已完成最小安全骨架和真实 Windows 命名管道测试；当前仅支持受认证的桌面在线探针，尚未接入配对、翻译、生词本或取消任务。

## 设计边界

- Windows 使用随机命名管道，不监听 TCP 端口，也不接受远程客户端。
- 桌面进程每次启动生成新的管道名和随机令牌，写入当前用户应用数据目录的 `browser-ipc.json`。
- 客户端先严格校验端点版本、管道名前缀和令牌格式；服务端使用定长比较校验令牌。
- IPC 消息使用 4 字节小端长度前缀和 UTF-8 JSON，读入正文前执行 64 KiB 上限。
- 当前唯一动作是 `probe`，只返回协议版本和桌面版本，不访问或返回 API Key、数据库、用户文本、文件路径和配置。
- 端点文件只由仍持有同一令牌的桌面实例删除，旧实例退出不能删除新实例的端点。

## 当前调用链

```text
Long翻译桌面启动
  -> 创建随机命名管道与令牌
  -> 原子发布 browser-ipc.json
  -> 接受多个本机客户端的受认证 probe
  -> 退出时按所有权清理端点文件
```

Native Host 到该管道的正式转发尚未启用。下一增量先让 Host 通过这个边界发起配对申请，并在桌面端实现明确的批准、拒绝和撤销状态；通过安全审计后才加入 `translate`、`cancel` 与 `add_word`。

## 验收门槛

- 正确令牌可连续探测两次，监听器不中断。
- 错误令牌被拒绝，且响应不包含桌面版本或其他桌面数据。
- 非法或超限端点元数据在连接前失败。
- 桌面退出清理自有端点；旧实例不得删除新实例覆盖后的端点。
- 日志不得记录令牌、请求正文或用户数据。

Chrome / Edge 的真实安装、`hello` / `ping`、升级和卸载烟雾仍是独立发布门槛，不能由 IPC 单元测试替代。
